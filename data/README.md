# 데이터 디렉터리 운영 지침

## 목적

원본 파일을 보존하고, 정리 중 데이터와 검수 완료 데이터를 분리한다. raw 원본은 제공 형식을 유지하고 working CSV는 중간 형식, reviewed 공용 canonical은 엔터티별 JSON으로 관리한다.

## 디렉터리

### `raw/`

- 사용자가 제공한 Excel, 강의 분석 텍스트 등 원본 입력 파일을 보관한다.
- 파일 내용과 원래 파일명을 변경하지 않는다.
- 파일명이 충돌하면 보관 경로나 메타데이터로 구분하며 raw 원본 이름을 바꾸지 않는다.
- 정리된 이름이나 영어 이름은 `working/` 또는 `reviewed/` 파생본에만 사용하고 `original_file_name`으로 raw 원본 이름을 추적한다.
- 병음, 한국어 뜻, 문제 유형, 답변이 없어도 정상이다.
- 수정·정규화가 필요하면 원본을 덮어쓰지 않고 `working/`에 파생 파일을 만든다.

### `working/`

- 원본에서 추출한 문제와 정리 중인 데이터를 보관한다.
- 중복 확인, 중국어 정리, 병음·한국어 추가, 유형 지정, 출처 검수를 수행한다.
- 불확실한 값은 추측하지 않고 빈 값 또는 확인 필요 상태로 둔다.
- 질문과 모범답안을 별도 데이터로 유지한다.
- 변환 결과에는 원본 파일과 시트·행·문단 등 위치를 추적할 정보를 남긴다.

### `reviewed/`

- 중국어, 병음, 한국어, 문제 유형, 출처가 검수된 문제를 보관한다.
- 검수 완료 공용 콘텐츠는 엔터티별 JSON을 canonical 형식으로 관리한다.
- 검수 완료 조건과 변경 이력을 확인할 수 있어야 한다.
- 실제 출처 문제와 자체 제작 변형 문제를 구분한다.
- 모범답안은 질문과 별도로 관리하며 `missing` 상태를 허용한다.

## 이동 및 수정 규칙

1. 원본은 내용과 원래 파일명을 유지한 채 `raw/`에 계속 보존한다.
2. 작업 시작 시 `raw/`를 직접 편집하지 않고 `working/` 파생 데이터를 만든다.
3. `working/`에서 질문 상태를 `raw` → `normalized` → `verified`로 검수한다.
4. 필수 검수를 통과한 결과만 deterministic 엔터티 JSON으로 `reviewed/`에 추가한다.
5. `reviewed/` 수정이 필요하면 변경 이유와 근거를 남기고 재검수한다.
6. 답변이 없다는 이유만으로 질문의 검수나 이동을 막지 않는다.
7. 파일을 삭제하거나 덮어쓰기 전에 원본과 파생본을 구분한다.

물리적으로 파일을 한 디렉터리에서 제거해 옮기기보다, 원본을 보존하고 단계별 파생 결과를 추가하는 방식을 기본으로 한다.

## 데이터 분리

- 공용 `Question`과 `ModelAnswer`
- 사용자의 개인 `UserAnswer`, 개인 `Correction`, `ReviewState`
- 강의 출처의 대표 `Correction`과 사용자 개인 `Correction`
- 확인된 출처 데이터와 `self_created` 데이터

위 범주는 같은 파일이나 표에 섞기 전에 분리 가능성과 출처 추적성을 검토한다.

`Correction`에는 학습 상태를 저장하지 않으며, 사용자별 `못 외움`, `헷갈림`, `외움` 상태는 `ReviewState`에서만 관리한다.

## 반입 전 확인

- 파일의 실제 출처와 원본 파일명
- 공개 저장소에 올릴 수 있는 자료인지 여부
- 개인정보, 비밀키, 계정 정보 포함 여부
- 암호화 또는 손상 여부
- 같은 원본의 중복본 여부

저작권 또는 개인정보가 불확실한 파일은 Git에 추가하지 않고 별도 확인한다.
