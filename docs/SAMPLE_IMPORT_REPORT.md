## 발견 사항

### 현재 스키마로 표현 가능한 필드

현재 `Question` 초안은 `question_id`, `source_id`, `source_locator`, Part, 유형, 중국어, 병음, 한국어, 상태와 정규화 기록을 직접 표현할 수 있다. 원본 행을 `source_locator`로 추적하는 방식도 20개 표본에 적용할 수 있었다.

### 추가 또는 구분이 필요한 후보

- `source_grade`, `originality`, `source_url`, 원본 `source_name`, `answer_point`는 현재 `Question` 필드에 직접 대응하지 않는다.
- `source_grade`는 자료 등급, `originality`는 문항의 원문·정규화·변형 성격이므로 의미가 다른 독립 축이다. 표본에서도 서로 다른 조합이 있어 둘 다 유지할 필요가 있다.
- `source_id = src-001`은 이 문제를 직접 추출한 workbook을 식별한다. `source_name`은 workbook 안에 적힌 주장된 출처 이름이므로 안정적인 식별자나 join key로 사용하지 않는다.
- `source_url`을 `Source`에 둘지, 한 질문과 여러 출처의 관계에 둘지는 추가 검토가 필요하다.
- `answer_point`에는 문항별 힌트, 답변 구조, 출처 주의 등 성격이 다른 내용이 섞일 수 있다. `Question`의 보조 필드, 별도 `AnswerPoint`, `PartGuide` 또는 provenance 정보로 분리할지 판단해야 한다.
- 공용 CSV에는 `연습 상태`, `최근 연습일`, `내 답변 메모`가 없으며 개인 학습 컬럼은 정상적으로 분리됐다.

## 검토 필요 사항

1. 원본의 `source_grade`, `originality`, `source_name`, `source_url`을 임시 raw 필드로 보존한 뒤 최종 스키마 위치를 정한다.
2. 직접 추출원인 `src-001`과 workbook이 주장하는 세부 출처 사이의 관계를 구분한다.
3. `answer_point` 값을 Part별로 분류해 단일 필드 또는 별도 엔터티 여부를 정한다.
4. Part 5~7과 그림·스토리 자료를 별도 표본으로 검증한다.
5. CSV, Excel, JSON 중 기준 데이터 형식은 전체 워크플로를 확인한 뒤 결정한다.

## 실행 및 원본 보존 검증

스크립트를 같은 원본으로 연속 실행했을 때 두 CSV의 SHA-256이 각각 동일했다. 원본 Excel의 작업 전후 SHA-256도 모두 `a150fd8a732d6ce2a309a6d5a41feb3788bb5b7b03142472d0d9fdf1fae1f37f`로 같았다. 원본을 저장하거나 수정하지 않았다.

`model_answers.csv`는 헤더 1행만 있으며 답변 데이터나 `answer_status = missing` 행을 자동 생성하지 않았다. 이 방식은 표본 검증용 임시 방식이다.
