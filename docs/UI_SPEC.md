# MVP UI 명세

## 문서 목적과 범위

이 문서는 데이터 스키마 v1과 모바일 목업을 바탕으로 MVP의 화면 구조, 표시 규칙과 상태를 정의한다. 구현 기술, 라우터, API, 데이터베이스와 저장 방식을 결정하지 않으며 실제 웹 앱 코드를 설명하지 않는다.

기준 목업은 [`docs/mockups/tsc-mock-v2.html`](mockups/tsc-mock-v2.html)이다.

- HTML title: `TSC 학습 · 목업 v2`
- 원래 경로: 저장소 루트의 `tsc-mock-v2.html`
- SHA-256: `9f93a18b10d752cdea606388b37984a89feb04fb598b0bd44baf8fe3ba4294ae`
- 역할: 화면 방향을 비교하기 위한 참고 자료

목업의 HTML, 스타일, 스크립트와 더미 데이터는 실제 서비스 코드나 canonical 데이터가 아니다. 기본 시각 방향은 Theme B를 참고하되 Theme A/B/C 전환은 목업 비교 기능이며 MVP 기능으로 확정하지 않는다.

## UI 설계 목표

1. 사용자가 홈에서 바로 Part 학습이나 오늘 복습을 시작하게 한다.
2. 중국어 답변의 실수를 줄이고 Part별 답변 구조를 반복 확인하게 한다.
3. 모범답안을 먼저 암기시키기보다 사용자가 자신의 답변을 작성한 뒤 비교하게 한다.
4. 공용 콘텐츠, 출처 답변, 개인 답변과 개인 오류를 명확히 구분한다.
5. 답변·가이드·출처가 없는 정상 상태와 실제 처리 실패를 구분한다.

## 모바일 우선 원칙

- 일반적인 모바일 반응형 웹을 기준으로 한다.
- 목업의 `body max-width: 480px`은 시안 표현용이며 실제 화면 폭을 480px로 고정하지 않는다.
- 작은 화면, 확대, 가로·세로 방향과 safe area에서도 주요 내용과 행동 버튼이 가려지지 않아야 한다.
- 태블릿 전용 레이아웃은 별도로 설계하지 않는다.
- 데스크톱에서도 모바일 학습 흐름을 유지하되 구체적인 breakpoint는 기술 선택 후 정한다.

## 전역 탐색과 하단 메뉴

하단 메뉴는 다음 네 개로 고정한다.

1. `학습`
2. `복습`
3. `나의 답변`
4. `실수 노트`

각 탭은 해당 기능의 시작 화면으로 이동한다. 하위 화면에서는 현재 소속 탭을 유지하고, 뒤로가기는 사용자가 진입한 화면 문맥으로 돌아간다. 구체적인 URL과 라우터 구조는 정하지 않는다.

## 전체 화면 목록

| 화면 ID | 화면 | 역할 |
|---|---|---|
| `HOME` | 학습 홈 | 오늘 복습, 이어서 학습, Part 1~7 진입 |
| `PART_DETAIL` | 파트 상세 | Part 목표·구조·표현·실수와 문제 목록 |
| `TEXT_QUESTION` | 일반 텍스트 문제 | Part 1·3·4·5·6의 질문 학습과 답변 작성 진입 |
| `PART2_VISUAL` | Part 2 그림 문제 | 그림 한 세트와 하위 문항 1~4 학습 |
| `PART7_STORY` | Part 7 스토리 문제 | 그림·공통 지시문·StoryGuide를 이용한 이야기 구성 |
| `ANSWER_EDITOR` | 답변 작성 | 한국어·중국어·혼합 입력과 교정 모드 선택 |
| `CORRECTION_RESULT` | 교정 결과 | 교정 결과 검토, 승인 저장 또는 다시 쓰기 |
| `REVIEW` | 복습 | 답변을 숨긴 회상과 개인 학습 상태 변경 |
| `MY_ANSWERS` | 나의 답변 | 승인해 저장한 UserAnswer 조회와 후속 행동 |
| `MISTAKE_NOTE` | 실수 노트 | 공용·개인 Correction 조회와 복습 |

화면 ID는 문서 안에서 사용하는 식별자이며 URL이나 컴포넌트 이름을 뜻하지 않는다.

## 핵심 화면 이동 구조

```text
학습 홈
├→ 오늘 복습 → 복습
├→ 이어서 학습 → 파트 상세 또는 문제
└→ Part 1~7 → 파트 상세
                 ├→ 일반 문제
                 ├→ Part 2 그림 문제
                 └→ Part 7 스토리 문제

문제
→ 답변 작성
→ 교정 결과
├→ 사용자 승인 후 저장 → 나의 답변
└→ 다시 쓰기 → 답변 작성

복습
→ 답변 보기
→ ReviewState 선택
→ 다음 항목

실수 노트
→ 잘못된 표현 회상
→ 올바른 표현 보기
→ ReviewState 선택
```

상세한 분기와 실패 흐름은 [NAVIGATION_FLOW.md](NAVIGATION_FLOW.md)를 따른다.

## 공통 컴포넌트

| 컴포넌트 | 역할 |
|---|---|
| 화면 헤더 | 화면 제목, 문맥을 보존하는 뒤로가기 |
| 하단 탭 | 네 개 핵심 영역의 전역 진입 |
| Part 항목 | Part 번호·이름·목표와 학습 진입 |
| 언어 묶음 | 중국어, 전체 병음, 한국어 뜻 |
| 구조 단계 | `PartGuide.response_structure` 또는 `AnswerPoint`의 순서 표시 |
| 질문 항목 | 안정적인 ID, 주제, 언어 묶음과 개인 답변 유무 |
| 시각 자료 영역 | `VisualSet`에 연결된 `VisualAsset`과 권리·로딩 상태 |
| 상태·출처 라벨 | 콘텐츠 검수, 답변 검수와 출처 확인 상태 |
| 답변 입력기 | 입력 언어에 제한을 두지 않는 원문 보존 입력 영역 |
| 교정 모드 선택 | 최소 교정, 자연스럽게, Level 8 확장 |
| 교정 전후 항목 | 수정 전·후 표현과 이유 |
| 답변 공개 제어 | 사용자가 명시적으로 답변을 공개하는 버튼 |
| 복습 상태 선택 | 못 외움, 헷갈림, 외움 |
| 빈 상태 안내 | 정상적인 데이터 부재와 다음 행동 |
| 로딩·오류 안내 | 처리 상태, 원문 보존, 재시도와 복귀 행동 |

클릭 가능한 카드나 목록 행은 키보드로 조작 가능한 링크 또는 버튼의 의미를 가져야 한다.

## 공통 언어 표시 규칙

표시 순서는 항상 다음을 기본으로 한다.

1. 중국어
2. 전체 병음
3. 한국어 뜻

추가 원칙:

- 검수 완료 또는 학습자 표시 데이터는 세 항목을 함께 제공한다.
- raw 또는 검수 중 데이터에 병음·한국어가 없으면 임의 생성하지 않는다.
- 병음 표시·숨김은 학습 보조 제어이며 원본 데이터를 변경하지 않는다.
- 숨겨진 항목은 빈 여백 대신 현재 표시 상태를 알 수 있게 한다.
- 중국어에는 중국어 언어 정보를, 한국어에는 한국어 언어 정보를 제공한다.

## 화면별 UI 명세

### 학습 홈

행동을 바로 시작할 수 있도록 다음 순서로 단순하게 구성한다.

1. 오늘 복습할 문제
2. 이어서 학습할 Part 또는 문제
3. Part 1~7 목록

복잡한 통계 대시보드는 제공하지 않는다. 복습 항목이나 이어서 학습할 항목이 없으면 해당 영역을 간단한 빈 상태로 표시하고 Part 목록은 유지한다.

`오늘 복습`은 별도로 정한 대상 선정 근거가 있을 때만 수량과 항목을 제시한다. 현재 스키마에 없는 복습 예정일을 추측하지 않는다. `이어서 학습`도 신뢰할 수 있는 마지막 학습 문맥이 있을 때만 구체적인 Part나 문제를 표시한다.

### 파트 상세

다음을 표시한다.

- Part 번호와 이름
- 학습 목표
- 준비 요령
- 권장 답변 구조
- 필수 표현
- 자주 하는 실수
- 해당 Part의 문제 또는 시각 학습 목록

필수 표현과 자주 하는 실수가 없으면 섹션 자체를 숨길 수 있다. 문제 목록은 선택한 Part의 관계를 기준으로 필터링하며 목업의 전체 더미 질문을 재사용하지 않는다.

### 일반 텍스트 문제

기본 순서는 다음과 같다.

1. 질문
2. 병음과 한국어
3. Part 답변 구조 또는 `AnswerPoint`
4. 내 답변 작성 진입
5. 교정 결과 확인
6. `ModelAnswer` 비교
7. 승인한 나의 답변 저장

`ModelAnswer`는 사용자가 답변을 작성하기 전에 강제로 펼치지 않는다. 답변이 하나도 없으면 `아직 모범답안 없음`을 표시하고 답변 작성은 계속 가능하게 한다.

### 답변 작성

- 한국어, 중국어, 두 언어가 섞인 입력을 모두 허용한다.
- 사용자가 입력한 원문은 교정 성공·실패와 관계없이 유지한다.
- 빈 입력은 교정 요청을 보내지 않고 입력 안내를 제공한다.
- 질문, Part 구조와 선택한 교정 모드를 함께 전달할 수 있는 화면 계약을 사용한다.
- 저장 전 교정 후보는 canonical `UserAnswer`가 아니다.

### 교정 모드

| 모드 | UI 동작 |
|---|---|
| 최소 교정 | 기본값. 사용자 단어와 문장 구조를 최대한 유지하고 필요한 오류만 고친다. |
| 자연스럽게 | 의미와 경험을 유지하면서 매우 부자연스러운 연결과 표현을 자연스럽게 정리한다. |
| Level 8 확장 | 최소 교정과 분리된 별도 결과다. 사용자가 말하지 않은 사실이나 경험을 만들지 않는다. |

세 모드 모두 원래 의미와 개인 경험을 유지하고, 사용자가 말하지 않은 사실이나 경험을 만들지 않는다. 사용자의 중국어 단어와 문장 구조는 선택한 모드의 목적 안에서 최대한 재사용한다. 질문과 관련 없는 내용은 임의로 바꾸지 않고 관련성 문제와 이유를 결과에 표시한다. 세 모드의 결과를 한 결과 안에 섞지 않는다.

### 교정 결과

다음을 표시한다.

- 교정된 중국어
- 전체 병음
- 한국어 뜻
- 수정한 개수
- 수정 전 → 수정 후
- 각 수정 이유
- 질문과의 관련성 문제
- 확인이 필요한 불확실성
- `나의 답변으로 저장`
- `다시 쓰기`

저장 버튼은 사용자의 명시적 승인을 뜻한다. 비슷한 문제 추천은 MVP 필수 기능으로 확정하지 않고 후속 후보로만 기록한다.

### 복습

복습 대상은 `Question`, `UserAnswer`, 개인 `Correction`, 공용 `Correction`이다.

```text
문제 또는 잘못된 표현
→ 숨겨진 답변 회상
→ 답변 보기
→ 상태 선택
→ 다음 항목
```

- `ReviewState` 레코드가 없으면 `상태 없음` 또는 `학습 전`으로 표시한다.
- 복습 이력이 없다는 이유로 `못 외움` 레코드를 자동 생성하지 않는다.
- 상태는 `못 외움`, `헷갈림`, `외움` 중 사용자가 직접 선택한다.
- 개인 상태는 `ReviewState`에서만 읽고 변경한다.
- 중국어·병음·한국어 표시를 조절하며 기본 복습에서는 병음을 숨길 수 있다.
- `ModelAnswer`가 없으면 `UserAnswer`만으로 복습할 수 있다.
- `UserAnswer`도 없으면 질문만 보고 회상하는 복습을 계속할 수 있다.

구체적인 다음 복습 날짜와 간격 알고리즘은 정하지 않는다.

### 나의 답변

목록에 다음을 표시한다.

- Part
- 안정적인 문제 ID
- 주제
- 중국어
- 병음
- 한국어
- 마지막 수정일
- 연결된 `Question`
- `ReviewState`에서 가져온 학습 상태

주요 행동은 문제 상세 이동, 답변 수정, 다시 교정, 삭제 또는 보관이다. 물리 삭제와 소프트 삭제 방식은 저장 기술을 결정할 때 정한다.

### 실수 노트

공용 오류와 개인 오류를 필터로 구분한다.

공용 오류:

- 검수된 강의 `Correction`
- 확인된 출처 또는 강의 정보
- 잘못된 표현과 올바른 표현
- 병음과 한국어
- 오류 유형과 수정 이유

개인 오류:

- `UserAnswer` 교정 과정에서 생긴 개인 `Correction`
- 원래 사용자 입력과의 연결
- 제공 가능한 경우 반복 횟수 또는 최근 발생 정보
- 개인 `ReviewState`

`Correction` 자체에는 학습 상태를 넣지 않는다. 개인 상태는 `ReviewState`에서 가져오며, 검수되지 않은 출처를 확정된 강사 표현처럼 표시하지 않는다.

## Part별 화면 차이

모든 Part에 같은 질문 상세 화면이나 Part 4 구조를 강제하지 않는다.

| Part | 전용 표시와 흐름 |
|---|---|
| Part 1 | 질문, 본인의 고정 정보 답변, 중국어·병음·한국어, 기존 답변 수정. 목표는 짧고 정확한 개인 정보를 막힘없이 말하는 것이다. |
| Part 2 | `VisualSet` → 큰 `VisualAsset` → `VisualQuestion` 1~4 → 현재 문항 → 언어 묶음 → 답변 작성 → 원본 추천 답변 또는 `ModelAnswer`. |
| Part 3 | 상대방 발화·상황과 `즉각 반응 → 이유·상황 → 후속 표현`, 답변 작성, 교정·비교. |
| Part 4 | `직접 답변 → 이유 → 설명·경험 → 결론`, 개인 화제 답변, 교정 결과와 모범답안 비교. |
| Part 5 | `입장 → 근거 → 예시·반론 → 결론`, 의견형 `AnswerPoint`, 긴 답변 작성과 교정. |
| Part 6 | 주어진 상황, 역할·요구 행동, `반응·사과 → 문제 설명 → 해결책·대안`, 답변 작성. |
| Part 7 | `VisualSet` → `VisualAsset` → 공통 지시문 → `StoryGuide` → 흐름·연결어 → 이야기 작성 → 교정 → 존재할 때만 `ModelAnswer` 비교. |

### Part 2 시각 문제 규칙

- 그림을 질문보다 먼저 충분히 크게 표시한다.
- 한 `VisualSet` 안에서 `VisualQuestion.item_number` 기준 문항 1~4를 이동한다.
- `VisualQuestion.question_id`가 비어 있어도 질문 자체는 정상 표시한다.
- 연결된 canonical `Question`이 없다면 임의의 `question_id`를 만들거나 연결하지 않는다.
- 원본 추천 답변이 `review_needed`이면 `원본 추천 답변 · 검수 필요`라고 표시한다.
- 검수 전 답변을 승인된 기본 모범답안처럼 표시하지 않는다.
- 독립 `VisualQuestion`의 답변 작성·교정 세션은 가능하지만, 현재 v1의 `UserAnswer.question_id`로 승인 저장할 수 없는 경우가 있다. 구현 전에 저장 대상 계약을 보완하며 가짜 Question 연결로 우회하지 않는다.

### Part 7 스토리 문제 규칙

- `StoryGuide`는 `이야기 구성 도움` 또는 `구성 포인트`로 표시한다.
- `StoryGuide`를 `모범답안`이라고 표시하거나 중국어 답변으로 변환하지 않는다.
- `QuestionVisualSet`이 검증되지 않았으면 Question과 그림을 강제 결합하지 않는다.
- 명시적으로 연결된 `VisualSet`과 `StoryGuide`는 있으나 검증된 `QuestionVisualSet`이 없으면 `연결 검수 중인 시각 연습`으로 별도 표시할 수 있다. 이 상태를 특정 Question 상세에 합치지 않으며, 답변 작성·교정 진입 여부와 승인 저장 대상은 계약 보완 전까지 제한 또는 보류한다.
- 같은 `question_zh`가 반복되어도 오류나 동일 문제로 처리하지 않는다.
- 안정적인 `question_id`, `visual_set_id`와 검증된 연결을 사용한다.
- `ModelAnswer`가 실제로 있을 때만 별도 비교 영역을 표시한다.

## 출처와 검수 상태 UI

내부 자료 등급 A/B/C/D를 주요 학습 화면에 그대로 노출하지 않는다.

사용자용 라벨 후보:

- `공식 샘플`
- `강의 확인`
- `공개 기출형`
- `연습 변형`
- `출처 확인 필요`
- `검수 필요`

표시 원칙:

- `SourceReference`로 확인할 수 있는 정보만 표시한다.
- `공식 샘플`과 `강의 확인`은 검증된 실제 `Source` 및 관계가 해당 성격을 뒷받침할 때만 표시한다.
- `claimed_source_name`, `claimed_source_url`, 내부 자료 등급이나 원문성 값만 있으면 공식·강의 출처로 단정하지 않고 `출처 확인 필요`로 표시한다.
- 검수되지 않은 링크를 공식 링크처럼 강조하지 않는다.
- 출처 정보는 문제와 학습 행동보다 작게 표시한다.
- 개발용 `source_locator`는 일반 사용자 화면에 노출하지 않는다.
- `review_needed`, `unverified_source` 답변은 검수된 `approved` 답변과 다른 라벨을 사용한다.
- 이미지 권리 상태가 공개를 허용하지 않으면 공개 화면에서 파일 표시를 강제하지 않고 대체 상태를 제공한다.

| 필터 결과 없음 | 필터 해제 행동 |

## 로딩·오류 상태

### 일반 데이터 조회 중·실패

- 홈, Part 목록, 문제 상세, 나의 답변, 복습 큐와 실수 노트의 최초 조회 중임을 텍스트 또는 구조가 유지되는 로딩 표시로 알리고 해당 영역에 처리 중 상태를 접근 가능하게 전달한다.
- 조회 결과가 비어 있는 정상 상태와 조회 실패를 구분한다.
- 조회 실패 시 다시 시도와 이전 화면으로 돌아가기를 제공한다.
- 일부 데이터를 이미 표시했다면 실패 때문에 이를 지우지 않고, 갱신되지 않은 영역과 재시도 행동을 구분한다.

### AI 교정 중

- 처리 중임을 텍스트로 알린다.
- 중복 요청을 방지한다.
- 사용자가 작성한 원문을 유지한다.
- 해당 영역에 처리 중 상태를 접근 가능하게 전달한다.

### AI 교정 실패

- 작성한 원문과 선택한 모드를 유지한다.
- 다시 시도, 직접 수정, 저장하지 않고 돌아가기를 제공한다.
- 실패한 결과를 `UserAnswer`로 자동 저장하지 않는다.

### 저장 실패

- 교정 결과 화면과 입력 내용을 유지한다.
- 다시 저장과 내용 복사를 제공한다.
- 성공한 것처럼 나의 답변 화면으로 이동하지 않는다.

### 복습 상태 저장 실패

- 사용자가 선택한 상태와 현재 항목을 유지한다.
- 재시도를 제공하고 성공 전에는 다음 항목으로 자동 이동하지 않는다.

### 이미지 로딩·권리 상태

- 이미지 파일 로딩 실패와 권리 미확인으로 인한 비표시를 구분한다.
- 대체 안내를 제공하며 `StoryGuide`나 답변 내용을 이미지 대체 텍스트로 추측하지 않는다.

### 네트워크 없음

오프라인 지원 여부와 저장 기술이 미결정이므로 구체적인 오프라인 동작을 약속하지 않는다. 현재 화면의 입력을 가능한 범위에서 유지하고 네트워크가 필요한 행동임을 알린다.

## 접근성 기본 원칙

- 색상만으로 학습 상태, 검수 상태와 오류를 구분하지 않는다.
- 버튼과 탭에는 아이콘뿐 아니라 텍스트 라벨을 함께 제공한다.
- 중국어, 병음, 한국어를 읽을 수 있는 충분한 글자 크기와 줄 간격을 사용한다.
- 교정 전후는 색상뿐 아니라 취소선, 화살표와 `수정 전`·`수정 후` 라벨로 구분한다.
- 답변 숨김은 blur만 사용하지 않고 공개 전에는 보조 기술에도 노출되지 않는 접근 가능한 숨김 상태를 사용한다.
- 키보드 포커스를 항상 볼 수 있게 하고 논리적인 순서로 이동하게 한다.
- `prefers-reduced-motion`을 존중한다.
- 하단 고정 메뉴가 본문, 입력 영역이나 행동 버튼을 가리지 않게 한다.
- 화면 전환, 답변 공개, 저장과 오류 발생 후 포커스를 적절한 제목이나 안내로 이동한다.
- 상태 변경과 저장 결과는 과도하지 않은 접근 가능한 알림으로 전달한다.
- 의미 있는 이미지 대체 텍스트는 보이는 장면만 중립적으로 설명하며 답이나 이야기를 추측하지 않는다.
- 답변 입력, 모드 선택과 필터에는 프로그램적으로 연결된 이름을 제공하고, 설명·필수 여부·오류 안내를 해당 컨트롤과 연결한다.
- 중국어 원문, 병음과 한국어는 각 표기 체계를 구분할 수 있게 마크업한다. 병음의 발음·읽기 언어 처리는 보조 기술 검증을 거쳐 정하며 중국어나 한국어 본문으로 잘못 단정하지 않는다.
- 확대 200%, 작은 화면, 키보드 전용 조작과 safe area를 확인한다.

구체적인 UI 라이브러리는 결정하지 않는다.

## 목업에서 실제 구현으로 넘어갈 때 주의사항

1. 현재 `openPart()`는 선택한 Part와 관계없이 `QS` 전체를 표시한다. 실제 구현은 `question.part` 또는 검증된 Part 관계로 필터링한다.
2. 현재 `QS` 더미 데이터는 Part 4 중심이며 모든 Part의 실제 데이터가 아니다.
3. Part별 답변 구조는 해당 `PartGuide`를 사용한다. 구조가 없다는 이유로 Part 4 구조를 기본 적용하지 않는다.
4. `P4-SPORT-001` 같은 값은 더미 ID다. 실제 구현은 canonical `question_id`를 사용한다.
5. 목업의 교정 결과와 `setTimeout` 처리는 하드코딩된 더미이며 실제 AI 응답 계약이 아니다.
6. 목업의 `ModelAnswer`는 예시 데이터이며 저장소 원본의 검수된 답변으로 간주하지 않는다.
7. 목업의 `MY` 객체와 저장 토스트는 더미 사용자 데이터·동작이며 실제 `UserAnswer` 저장 방식이 아니다.
8. `question_zh`를 화면 식별자나 URL 키로 사용하지 않는다.
9. Part 2와 Part 7은 별도의 시각 문제 화면을 사용한다.
10. 목업의 Theme A/B/C 전환은 MVP 확정 기능이 아니다.
11. `body max-width: 480px`은 목업 표현용이다. 실제 구현은 일반 모바일 반응형으로 동작하며 태블릿 전용 설계는 하지 않는다.

추가로 목업의 CSS blur는 접근 가능한 답변 숨김이 아니고, 고정 복습 일정 문구·비슷한 문제·외부 폰트 CDN·메모리 저장은 제품 또는 기술 결정으로 채택하지 않는다. 목업 HTML에서는 이러한 문제를 직접 수정하지 않는다.
